# Minimum Graph Coloring benchmarks

These deterministic course benchmarks support Checkpoint 1 readiness checks and Final Project experiments.

Required suites in `manifest.json`:

- `readiness` — small smoke tests for the Checkpoint 1 exhaustive baseline.
- `exact_frontier` — three known-optimum families for comparing exhaustive and improved exact search.
- `quality_known` — larger instances with known chromatic number for direct heuristic-quality measurement.
- `heuristic_scale` — sparse planted-coloring graphs through 5,000 vertices.
- `structure` — graphs with fixed `n=300` and `OPT=8` but different edge densities.

All synthetic instances are generated by `tools/generate_minimum_graph_coloring_benchmarks.py`. The generator plants a clique of size `k` and adds edges only between known color classes. Therefore each planted instance is both `k`-colorable and contains a `K_k`, proving that its chromatic number is exactly `k`.

## External DIMACS/COLOR open challenge

After your project has been assigned, run:

```bash
python tools/setup_project.py
```

For Minimum Graph Coloring, setup installs 20 externally sourced DIMACS/COLOR
instances into `external/dimacs/instances/`.  The selected challenge combines
long-standing hard/open DIMACS random instances, eight real optical-network
coloring graphs, and two structured hard instances.  The source files are not
committed to Git; the tracked manifest records the original instance name,
download location, source collection, and any published reference bound used by
the course.

Run the open challenge with:

```bash
python tools/run_experiments.py --suite challenge_open
```

`known_optimum = null` means the course is not claiming a certified chromatic
number for that instance.  A `best_known` value is only a published feasible
coloring and must not be described as optimal unless a cited reference proves it.
